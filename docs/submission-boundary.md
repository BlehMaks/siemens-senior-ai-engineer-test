# Submission boundary

## Intended repository contents

The final submission should contain only material needed to understand, run, test, and review the solutions:

- source code and tests;
- task READMEs and architecture decisions;
- reproducible dependency and build files;
- infrastructure definitions and safe configuration examples;
- diagrams stored as source plus rendered output when useful;
- small, redistribution-safe fixtures needed by automated tests.

## Local-only material

The following stays outside Git history and remote branches:

- private development instructions and local tooling configuration;
- private planning notes, alternative drafts, raw reviews, and brainstorming records;
- scratch work, progress logs, review transcripts, and temporary artifacts;
- API keys, credentials, local environment files, and cloud state;
- model weights, caches, benchmark traces, and generated runtime data;
- the original assignment document;
- supplied datasets until redistribution permission or the expected private-repository workflow is confirmed.

Before any push, the staged diff and outgoing commits must be inspected directly. Ignore rules are a safeguard, not proof that the publication set is correct.
